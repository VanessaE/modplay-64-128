The multirate routines are run once, at the very end of the loader
(after unroll_mod_sample_loops), and are used to build decimated copies
(1/2, 1/4, 1/8, 1/16 rate = levels 1..4) of every sample from the finished,
possibly-unrolled data that'll be sitting in the REU after the load.

Level 0 is the original data and is never touched.

In the multirate routines' tables, the index for a given level L (1..4),
and sample S (0..31) is (L-1)*32 + S.

Since the majority of the load buffer i.e. sample data buffer is unused when
multirate is active, the multirate code's variables and tables, which would
otherwise take up a lot of RAM, are stored up there instead.  Only the first
page of that buffer gets used for live audio cache versus half of the buffer.


###############
LOADER HOOK (loader-common.s), at file_size_okay: the last two lines

       jsr load_sample_data
       jmp unroll_mod_sample_loops

become

       jsr load_sample_data
       jsr unroll_mod_sample_loops
       jmp multirate_generate_all

(unroll_mod_sample_loops ends in an rts, so jsr is fine; .C comes back
clear if there wasn't enough REU for the multirate data.)


###############
DATA LAYOUT (for checking REU dumps)

Region for (level L, sample S) starts at multirate_sample_start_addresses_*
[(L-1)*32+S], page aligned, never crossing a 512k boundary.  Contents = the
final level-0 data from the sample start, passed L times through pairwise
averaging, (a+b)>>1, per 256-byte page.  Looped samples: loop start/end =
start + (offset >> L), start + offset' + ((loop length + half a step) >> L),
and the end addr equals the loop end addr.  After the end addr (loop end for
looped samples) there are MULTIRATE_GUARD bytes: the first MULTIRATE_GUARD
bytes of the decimated loop, or $80s for unlooped samples.


PLAYER-SIDE MULTIRATE, STAGE 1  (multirate branch)
==================================================
Static edit, not assembled or run.  Hunks are diff-style; match on the context.
The multirate pass itself is in the new multirate.s (unified level*32+sample
tables, level 0 copied in, no loop-end tables).

Build switch:  multirate is used only in oldskool builds (no turbo_available).
Everything below that is multirate-only sits behind  !ifdef use_multirate ,
so turbo builds assemble the old code paths.  Where possible the code is
common to both builds (idx = sample number and play_* = the loader's own
tables in turbo builds).

Layout decision this relies on:  the four 16-byte track caches are packed into
the FIRST page of sample_data_buffer (offsets 0,16,32,48), because the
multirate tables start at sample_data_buffer+256.
