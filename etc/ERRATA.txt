####################
##  KNOWN ISSUES  ##
####################

* ALL memory drivers: need to check that file will fit before loading,
  else throw an appropriate error.

* BOTH: The STOP wedge loader fails under some odd conditions, such as on
  C64 with JiffyDOS, on C128 with SuperCPU, and C128 with RAMLink if CMD HD
  parallel is available, leading to hangs, crashes, etc. The automatic loader
  selector compensates for these just fine, it just means slower loads than
  should otherwise be possible.

* BOTH: The loader needs REU 512 kB-wraparound mitigation, done in such a way
  as to minimize any performance impact on the mixer/fetch code.  Idea for
  that:  align each sample start point to a page boundary, then when iterating
  through the data, if an increment results in a page value of $FE and a bank
  value of (BANK AND 7) = 7, bump up to the next bank and continue from page
  0, thus entirely ignoring the last two pages of the 512 kB segment.  The
  fetch code will require a similar check, but it shouldn't be expensive.

  The C128 memory driver will require a similar mitigation, albeit with
  different boundaries, as the first and last portions of each bank above 0
  are unusable for file data.

* BOTH: all sample loops need to be unrolled to a minimum length of around
  10 kB or so and appended to the end of the sample, ending with one final
  copy of the first 256 bytes of the loop (or the whole thing if it was less
  than that), whether it needed unrolled or not.  This will minimize the load
  on the mixer and ensure that it won't cause the lookahead code to give bad
  data to the mixer when it reaches the end of the loop.

* BOTH: on samples that have no looping, the loader needs to pad the end of
  the sample with 256 bytes of silence, so that when the fetch code gets to
  the end of the sample, it won't cause the lookahead code to give garbage
  data to the mixer (after it runs through whatever it wants, the fetch code
  eventually land on and then stay within the "silence zone" in bank 0).

* C128: cursor-left in main menu triggers switch pages code

* BOTH: strings that should be centered are off by one: disk name is 1 to the
  left, file size in loader is 1 to the right.

* C64: if list is positioned not to fill the pane (e.g. close to start or
  end), file sizes aren't shown properly at bottom when scrolling with cursor
  keys (but page up/down, top/bottom, and C128 are all fine)

* C128: the displayed file name in infobox overwrites "Current".

* BOTH: sometimes, the filename displays as garbage in the mini popup when
  loading, yet the file will still load just fine.

* BOTH: progress bar has a minor off-by-1 overflow glitch.

* C128: "$" crashes on real hardware if the dir listing scrolls, but it only
  happens on a friend's machine, not on my C128-DCR, and it's fine in VICE
  too.

* C128: the single sample player just crashes, but it's supposed to pop-up a
  placeholder and then exit on keypress, or at least I thought I had it set to
  do that.

* BOTH:  program hangs when trying to load from a VICE virtual filesystem
